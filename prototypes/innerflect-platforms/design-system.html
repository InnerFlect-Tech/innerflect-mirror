Design principles

Innerflect should feel composed, technically credible and unusually calm. We use structure to build trust, then spend expressive energy on one meaningful interaction or visual moment.

Architecture before decoration

Grids, labels and hierarchy explain how something works. Every structural device must carry information.

One memorable signal

Each page earns one signature effect. Everything else supports it with restraint.

Visible quality

Show compatibility, maintenance, complexity and licensing wherever a user evaluates a system.

No generic AI gloss

Avoid arbitrary gradients, excessive glass, random icons and vague claims that could belong to any technology company.

System architecture

The local pattern library remains the visual source of truth. GetLayers contributes a useful shop taxonomy; mature design systems add the implementation layers that make those assets reusable and governable.

Primitive values describe scale. Semantic tokens describe intent, so components stay consistent when density, viewport or brand context changes.

Content rules

Use concrete nouns and active verbs. Product pages help someone judge fit quickly; they do not hide uncertainty behind aspirational language.

Say what the system contains

“14 modules, source verification and a governance checklist.”

Avoid empty transformation claims

Do not say “unlock limitless innovation” or “revolutionize your workflow.”

Name the action consistently

Copy prompt → Prompt copied. Save system → System saved.

Expose evaluation signals

Complexity, dependencies, update date, licence, performance cost and expected outcome.

Governance & release

Consistency is a maintenance practice. Each addition needs an owner, acceptance criteria, accessibility evidence, version status and a documented reason to exist.

PROPOSE

Show the gap

Document the user need, affected surfaces and why an existing pattern cannot solve it.

REVIEW

Test the contract

Visual consistency, responsive behaviour, accessibility and Forge/OS compatibility.

RELEASE

Version the change

Publish tokens, code, usage, migration note and screenshot together.

MEASURE

Watch adoption

Track duplication, defects, accessibility failures and time-to-build.
